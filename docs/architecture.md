# 架构

React + TypeScript + Vite 构成前端，Zustand 管理状态；Cloudflare Worker 提供静态资源和同源代理，无常驻业务后端。

## 模块职责

| 位置                                                   | 职责                                                            |
| ------------------------------------------------------ | --------------------------------------------------------------- |
| [types.ts](../src/types.ts)                            | 领域数据契约                                                    |
| [providers](../src/providers)                          | 接口适配、能力归一化与请求校验；配置维护见[模型文档](models.md) |
| [store](../src/store)                                  | 领域操作、供应商与任务状态、持久化协调                          |
| [lib](../src/lib)                                      | 存储、迁移、素材规则等窄职责逻辑                                |
| [agent](../src/agent)                                  | 通过统一适配器执行对话与工具调用                                |
| [views](../src/views)、[components](../src/components) | 页面组织与局部交互                                              |
| [worker](../worker)                                    | 无状态代理与静态资源入口                                        |

## 消息反馈

消息模型与策略在 [notices.ts](../src/lib/notices.ts)，运行状态由 appStore 管理。浮层、最近消息和详情共享记录；关闭浮层不删除记录，记录仅保留在内存中。输入与任务提示共用 [Feedback](../src/components/ui/Feedback.tsx)，任务状态仍由所属模块保存，图片生成失败保留在所属会话，成功重试后清除。确认操作共用 [ConfirmDialog](../src/components/ConfirmDialog.tsx)，异步操作完成后关闭，失败时保留确认框以便重试。展示与用词遵循[开发规范](../CONTRIBUTING.md#消息反馈)。

## 数据边界

- 供应商实例与接口协议分开；连接元数据不含 Key，运行配置按连接绑定凭据。模型请求使用服务商原始 ID，显示名称不参与能力判断。
- 保存供应商时，Key 写入当前浏览器 localStorage；旧 sessionStorage 凭据仍可读取，再次保存该供应商后转为长期保存。开启该连接的 Worker 代理后，Key 会随 API 请求经过 Worker；Worker 仅转发，不主动持久化 Key 或输出密钥日志。
- 删除供应商会移除该连接、凭据和模型，重新选择可用的创作与对话模型，并清除指向已删除模型的润色选择；已有对话、草稿、作品和视频任务保留。删除不会取消远端视频任务，缺少原连接时任务查询会暂停，不借用其他供应商的凭据。
- 能力声明与生成参数分开；发现、手动配置、历史恢复和请求发送前均需约束能力，旧缓存不能绕过当前限制。
- Studio 与 Chat 草稿的附件引用独立，图片与视频创作草稿分别保留。解除素材引用不等于删除资产；删除会话保留作品，资产的会话引用允许悬空。
- Chat 发送历史时按消息附件引用恢复仍存在的图片内容，缺失附件跳过；纯文字模型仅发送历史文本，原消息与附件保留，切回识图模型可继续使用。历史截取规则见 [ChatPanel.tsx](../src/components/ChatPanel.tsx)。
- 持久化与迁移入口在 [storage.ts](../src/lib/storage.ts) 和 [migration.ts](../src/lib/migration.ts)。读库失败不作为空库启动；普通自动保存尚未统一提供写入失败恢复提示，内存更新不代表落盘成功。
- `imageEditing` 与 `image.supportsEdit` 是历史兼容镜像，写入与恢复保持一致。其他字段直接查类型，不维护第二套字典。

## 视频任务

[videoTasks.ts](../src/store/videoTasks.ts) 管理提交、轮询、取消和恢复，不依赖页面组件生命周期。

- 创建远端任务前先保存本地记录；记录保存模型与连接地址快照，不保存 Key。
- 提交结果不明时不自动重建任务，允许补充远端任务编号恢复查询；查询错误不覆盖生成状态，凭据或连接变化时暂停查询。
- 页面隐藏或离线时暂停查询；重新打开后按记录恢复。删除会话不取消后台任务，删除任务卡不删除作品。
- 视频作品与任务的已保存标记在同一事务写入；作品保存上游链接，不等于已离线保存视频。
- 取消前检查远端排队状态，取消后查询确认；上游缺少原子条件取消，仍存在状态变化窗口。

## 网络边界

每个供应商连接独立保存「Worker 代理」，默认关闭；没有该字段的旧连接也按直连恢复，旧全局网络模式不再参与路由。模型列表、对话、润色、图片生成和视频任务提交、查询、取消均使用实际连接的设置；Agent 的文本与图片工具可分别走不同路径。开关开启后，自定义网关也统一经 Worker，请求失败不自动切换路径。页面由 Worker 托管与 API 请求路径独立。

[目标校验](../src/lib/proxy.ts)与[Worker](../worker/index.ts)限制代理目标、方法、请求来源及转发头，拒绝上游重定向；DELETE 仅允许视频任务取消路径。直连网络失败、Worker 拒绝或不可用、上游服务错误分别提示。媒体下载不携带 API Key，不提供任意媒体代理。允许范围的配置与部署边界见[部署](deployment.md#代理允许目标)。
